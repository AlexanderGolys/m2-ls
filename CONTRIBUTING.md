# Contributing

`m2-ls` is a single Rust crate at the repository root. Keep changes focused on
the crate unless a task explicitly touches repository docs or metadata.

## Where things live

```text
src/
  main.rs                 stdio executable entry point
  lib.rs                  shared modules and language-server protocol wiring
  cli.rs, bin/            standalone m2-lint and m2-fmt commands
  document.rs             versioned snapshots: source, parse tree, analysis
  source.rs               indexed source text and the single position-conversion API
  analysis.rs, analysis/  staged analysis: scopes, bindings, installations, typechecking
  typesystem.rs           static type inference over the object facts
  node_metadata/          per-node facts produced by analysis and consumed by features
  object_registry.rs      canonical object identities and registry lookup
  builtin_index.rs        in-memory form of the builtin corpus
  catalog.rs              external catalog download, verification, and caching
  package_index.rs        imported-package discovery and source-file resolution
  source_package.rs       packages declared in source: sections, exports, TEST blocks
  workspace_index.rs      cross-file index of top-level definitions
  diagnostics.rs, diagnostics/  every diagnostic: catalog, checks, rewrites, publication
  documentation.rs        Markdown documentation attached to source items
  settings.rs             initialization and live workspace configuration
  capabilities/           one module per LSP feature
  data/m2-index.schema.json  wire format of the external builtin corpus
```

Analysis runs first and records what it learns on syntax nodes; the modules in
`capabilities/` read those facts rather than re-deriving them. Treat every
`target/` directory as build output.

## Development

Run Cargo from the repository root. `cargo run` starts the server on stdio;
point an editor at `target/debug/m2-ls` after `cargo build` to try a change.
`./install.sh` installs this checkout and prepares the external catalog. It
accepts Cargo install options, including `--root` for an isolated installation.

Before committing, run:

```sh
cargo fmt -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test
cargo build
cargo package --allow-dirty
```

The build is expected to be warning-free. For LSP behavior changes, also test
through an editor client when practical. Non-ASCII text matters: LSP positions
are UTF-16, while Tree-sitter positions are byte-based.

## Builtin metadata

The builtin catalog is a separately downloaded artifact: one JSON record per line,
generated by the M2Book package from Macaulay2's documentation and runtime
metadata. Generation belongs to M2Book; running the server needs neither M2Book
nor Macaulay2. Do not hand-edit the corpus; regenerate it in M2Book instead.
The leading `{"kind":"meta", ...}` record (the
default-loaded package baseline) is mandatory; the server fails fast at startup
without it. The catalog is never embedded in the executable or included in the
crate archive.

The catalog is published as the `m2-index.jsonl` asset of each M2Book release,
next to its `m2-index.jsonl.sha256` checksum. The server follows the latest
release and refuses a download that does not match the wire format, so release
an incompatible format change together with the server that reads it.

Tests use the same catalog loader as the server. They download the latest
catalog once and then work offline. To use a local copy instead, set
`M2_LS_CATALOG` to its absolute path before running Cargo. Keep local copies
outside tracked source; `/m2-index.jsonl` is ignored for this purpose.

## Documentation

Keep `README.md` short and user-facing: what the server does, how to install
and connect it, and the settings it accepts.
