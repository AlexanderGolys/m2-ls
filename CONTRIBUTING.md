# Contributing

`m2-ls` is a single Rust crate at the repository root. Keep changes focused on
the crate unless a task explicitly touches repository docs or metadata.

## Where things live

```text
src/
  main.rs                 stdio executable entry point
  lib.rs                  shared modules and language-server protocol wiring
  cli.rs, bin/            standalone m2-lint and m2-fmt commands
  document.rs             versioned snapshots: source, parse tree, analysis
  source.rs               indexed source text and the single position-conversion API
  analysis.rs, analysis/  staged analysis: scopes, bindings, installations, typechecking
  typesystem.rs           static type inference over the object facts
  node_metadata/          retained parsed cells, the syntax snapshot, Markdown parsing
  syntax.rs               shared structural operations on generated expressions
  object_registry.rs      canonical object identities and registry lookup
  builtin_index.rs        in-memory form of the builtin corpus
  catalog.rs              external catalog download, verification, and caching
  package_index.rs        imported-package discovery and source-file resolution
  source_package.rs       packages declared in source: sections, exports, TEST blocks
  workspace_index.rs      cross-file index of top-level definitions
  diagnostics.rs, diagnostics/  every diagnostic: catalog, checks, rewrites, publication
  documentation.rs        Markdown documentation attached to source items
  settings.rs             initialization and live workspace configuration
  capabilities/           one module per LSP feature
  data/m2-index.schema.json  wire format of the external builtin corpus
```

Macaulay2 parsing goes through the released `m2-syn` API using its native
parser. Each retained cell owns its generated `Cell` directly; unchanged cells
share their allocation across document revisions. `SyntaxSnapshot` owns the
revision's cells and is the entry point for generated visitors. Typed spans map
to the current revision through `SourceNavigation`, including comments and
failed cells. There is no second syntax representation: features walk generated
nodes with `Visit` and read generated fields. `tests/architecture.rs` fails if
an untyped layer returns or a capability parses on its own.

Analysis runs first and records semantic facts; the modules in `capabilities/`
read those facts rather than re-deriving them. Shared structural operations
(delimiters, arguments, assigned functions) live in `syntax.rs` as extension
traits on generated nodes; option, property, and quoted symbol roles follow the
same pattern.

Expression inference lives in `analysis/inference/`. Generated constructs
implement their own `InferType` rules and follow typed operand fields. A session
borrows one syntax revision and caches results by expression allocation and
lexical scope; source-span equality does not identify an expression. Operator
spellings come from lexical tokens, excluding attached trivia. New expression
rules must not recover types through runtime casts. Ring values and specialized
operators live in `analysis/ring/values.rs`, using generated operands and the
same session cache. Generator syntax is shared through `analysis/ring/syntax.rs`.
Binding value ranges locate retained typed expressions; they do not replace
allocation identity in the inference cache.

Formatting runs on one `SyntaxSnapshot`: whitespace edits are collected by typed
visitors and applied through `LayoutSource`, which maps original syntax spans to
the edited text without reparsing between passes.

Treat every `target/` directory as build output.

## Development

Run Cargo from the repository root. `cargo run` starts the server on stdio;
point an editor at `target/debug/m2-ls` after `cargo build` to try a change.
`cargo install --path . --locked` installs this checkout on all supported
platforms. Use `--root` for an isolated installation. The optional catalog is
prepared automatically on first use.

Before committing, run:

```sh
cargo fmt -- --check
cargo clippy --workspace --all-targets --all-features -- -D warnings
cargo test
cargo build
cargo package --allow-dirty
```

The build is expected to be warning-free. For LSP behavior changes, also test
through an editor client when practical. Non-ASCII text matters: LSP positions
are UTF-16, while parser spans use byte offsets.

## Builtin metadata

The builtin catalog is a separately downloaded artifact: one JSON record per line,
generated by the M2Book package from Macaulay2's documentation and runtime
metadata. Generation belongs to M2Book; running the server needs neither M2Book
nor Macaulay2. Do not hand-edit the corpus; regenerate it in M2Book instead.
The leading `{"kind":"meta", ...}` record (the
default-loaded package baseline) is mandatory for a usable catalog; the server
continues with source analysis when no valid catalog can be loaded. The catalog
is never embedded in the executable or included in the crate archive.

The catalog is published as the `m2-index.jsonl` asset of each M2Book release,
next to its `m2-index.jsonl.sha256` checksum. The server follows the latest compatible `0.1.*`
release by default (`M2_LS_CATALOG_VERSION` accepts Cargo-style constraints)
and refuses a download that does not match the wire format, so release an
incompatible format change together with the server that reads it.

Tests use the same catalog loader as the server. They download the latest
compatible catalog once and then work offline. To use a local copy instead, set
`M2_LS_CATALOG` to its absolute path before running Cargo. Keep local copies
outside tracked source; `/m2-index.jsonl` is ignored for this purpose.

## Documentation

Keep `README.md` short and user-facing: what the server does, how to install
and connect it, and the settings it accepts.

The guide in `docs/` is built with `mdbook-tsitter` 4 or later. Its `m2` blocks
carry the server's semantic tokens as `§type.modifier|text§` marks, which the
build turns into styled spans (`lsp = true` for `macaulay2` in `docs/book.toml`).
Write a new block as plain code, then generate its marks with the server
installed as `m2-ls`:

```bash
nvim --headless -l tools/lsp-marks/headless.lua block.m2 --server=m2-ls
```

`tools/lsp-marks` is in the `mdbook-tsitter` repository. The server returns no
tokens for a cell with a syntax error, so illustrations of unfinished input
stay unmarked.

## Test logging

Tests must not write to the usage history or operational log. Library tests do
not initialize file writers. Every test subprocess running a tool must set both
`M2_LS_USAGE_LOG=off` and `M2_LS_LOG=off`, even if the parent process enables
logging. Exercise event formatting through in-memory output instead.
